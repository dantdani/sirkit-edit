## Owner decisions (PROPOSED — nothing changed without you)

1. **DRC preset annular ring** — `jlcpcb-2l.json` uses one `minAnnularRingMm 0.15` for vias and PTH pads. JLCPCB states PTH absolute minimum 0.18 mm (recommended 0.25 mm). Proposal: split the rule into `minViaAnnularRingMm` (0.15 is conservative vs hole+0.1 mm) and `minPthAnnularRingMm ≥ 0.18` (or 0.25), then re-verify and re-record the fixtures. The acceptance board's PTH pads (0.35 mm ring) already satisfy 0.25 mm.
2. **Reviewer role for component binding** — `bind_atomic_selection` requires a human `reviewer`/`project_admin` (`PB_ATOMIC_BIND_HUMAN_REVIEWER_REQUIRED`, mapped to HTTP 422 by the existing route). A `pcb_editor` therefore cannot complete "Schematic → PCB" alone on a fresh project. Decide whether editors may bind (policy) or whether the UI should route editors to a reviewer hand-off; this stage documents the current truth and does not change the policy.
3. **Design changes after qualification** — a routed board refuses structural re-synchronization (`PS_STRUCTURAL_ADD_REQUIRES_UNROUTED_BOARD`, `PS_REMOVED_NET_PROTECTED`; Stage 8 copper protection). The product currently offers no durable "clear routing / start a new board revision" command, so a post-qualification schematic change cannot reach the PCB through the UI. Recovery H.13 proves the invalidation semantics through the durable repository seam. Decide the Stage 8 path (durable rip-up / new board instance).
4. **Physical-binding status code** — refusing a non-reviewer with HTTP 422 (not 403) is existing behaviour; consider mapping `HUMAN_REVIEWER_REQUIRED` to 403 (one-line change in `app/api/physical-bindings/route.ts`; two tests pin the current 422).
5. **Snapshot revision reconciliation policy** — the editor now adopts the server's snapshot head over browser memory. If a browser is mid-way through a sync that another session superseded, the server still refuses with 409 (`PS_SNAPSHOT_REVISION_CONFLICT`) — no silent overwrite. Decide whether the UI should surface "another session published" explicitly.
6. **Fabrication profile evidence refresh cadence** — `verifiedAt: 2026-09-07` expires for release after 366 days (`MFG_RULE_PROFILE_STALE_AT_RELEASE`). Someone must re-verify against the official page and update the constant (and the preset `verifiedAt`) before 2027-09-08.
