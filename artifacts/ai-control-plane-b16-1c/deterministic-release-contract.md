## Independent validators (do not reuse generator decision logic)

1. `app/lib/pcb/fab/independent-archive-verifier.ts` — own RS-274X and Excellon lexers, own canonical-JSON digest, cross-checks outline bbox vs manifest board size, copper flashes/draws vs pad/track counts, drill hits vs plated-hole count and tool diameters vs profile, holes ↔ bottom-copper flashes, job file ↔ shipped members, member digests ↔ manifest, release id ↔ digests, fixed timestamps. 80 PASS rows on the acceptance archive: 78 unconditional rows for a 10-member / 9-manifest-file / 6-Gerber archive plus the 2 expectation rows the acceptance suite passes (`boardRevision`, `expectedComponents: 9`; `acceptance-pipeline.test.ts` line 352) — counted from the source in B16-A (CONFIRMED). The rows are written to `<evidence dir>/b16-1c-acceptance-evidence.json` → `archiveChecks` (`SIRKIT_B16_1C_EVIDENCE_DIR` or the OS temp dir — never `scripts/output`, which the B16.1C fix moved away from; [B16-A corrected] this line previously named `scripts/output/…`).
2. `scripts/verify-release-independent.py` — third-party `gerbonara 1.6.3`; pre-existing script (present at `b7bb6d6`, added in commit `3505cd8`), run LOCALLY only — no `.github` workflow and no `package.json` script invokes it (CONFIRMED). It uses the manifest ONLY to locate files by role, then checks: layer presence (7 roles), parseability of copper/mask/silk/outline, outline real extent, outline within the 100 × 80 mm envelope, outline closure (no dangling segment endpoints), drill parse, tool diameters readable and ≥ 0.30 mm with exact decimals, top copper and every hole inside the outline bounding box, bottom copper inside the same frame, full-stack auto-detection. It does NOT recompute or compare the manifest content digest, member sha256s, the release id, or any pad/track/hole COUNT against the manifest — those checks exist only in reader 1.
